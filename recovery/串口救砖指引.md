# 串口救砖指引

> **本仓库不覆盖串口救砖。** 本文只说明什么时候需要、并指向权威资料。

## 什么情况下需要串口救砖

**软砖**：设备本身没坏，但**改坏了系统启动流程**，导致开机停在 logo、黑屏、反复重启、进不去任何界面。

LanguageBreak / KUAL / KOReader 这套越狱路线**本身不会让设备变软砖**——越狱走的是热补丁加载器，不覆盖内核。但下列操作可能：

- 手动禁用系统服务（尤其是 `demd`，见下文"预防"）。
- 手动修改 `/etc/init.d/rcS` 之类的开机脚本。
- 手动替换系统二进制（`otaupd`、`otav3`、`libsystem.so` 等）。
- 通过 SSH 或 telnet 改系统关键路径。

这些操作走的是"越狱之后的手动改造"路径，一旦出错，USB 完全无响应、连 LanguageBreak hotfix 都打不了，只能**拆机用 UART 串口**进去救。

## 本仓库的定位

- 本仓库覆盖 **LanguageBreak 正常路径 + 常见偏离状态**（见 [README.md](./README.md) 的状态清单）。
- 串口救砖是**改坏系统之后**的最后一道救命绳，属于**越狱之后的手动改造**范畴，本仓库不覆盖。
- 我们**不鼓励**在没有必要的时候动系统服务；越狱 + KOReader + 微信读书这条主路径不需要动它们。

## 预防：不要动 demd

**`demd`** 是 Kindle 启动流程里的一个关键服务。多个社区实测反馈**禁用 `demd` 会导致设备变砖**，串口进去才能救回来。

- `zzwcoding/weread-kpw3` 的 `docs/04` 记录了 `demd` 被禁后变砖的完整恢复过程。
- 本仓库不修改 `demd`；如果你的越狱脚本或改造方案里出现"禁用 demd"步骤，请重新评估必要性。

## 遇到软砖怎么办（决策树）

```
软砖 → USB 能识别盘符吗？
   ├─ 能 → 试 USB 修复（比如重打 hotfix，见 越狱桥接挂了.md）
   └─ 不能 → 试官方逃生开关 DO_FACTORY_RESTORE（见 越狱桥接挂了.md）
            ├─ 恢复出厂成功 → 从步骤 0 重来
            └─ 恢复出厂也没反应 → 只能串口救砖（去 zzwcoding/weread-kpw3）
```
